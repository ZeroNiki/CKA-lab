# CKA Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Локальный CKA-тренажёр: уровни (теория-допуск + 7 практических заданий в kubeadm-кластере), автоматическая проверка, койны и перерывы, режимы Mixed и Practice only, откат через snapshot.

**Architecture:** Vagrant/libvirt поднимает кластер из 3 нод; bash-CLI `./lab` управляет стендом и сервером. Go-сервер (один бинарник, UI через `embed`) загружает контент из YAML, выполняет декларативные проверки через `client-go` и SSH, хранит прогресс в JSON. Frontend: Vue 3 без бандлера.

**Tech Stack:** Go 1.26 (nixpkgs), `k8s.io/client-go` v0.37.2 (+ `k8s.io/api`, `k8s.io/apimachinery` той же минорной), `golang.org/x/crypto/ssh`, `sigs.k8s.io/yaml`, Vue 3 (vendored ESM), Vagrant 2.4.9 + vagrant-libvirt 0.12.2, kubeadm v1.37, Calico, Envoy Gateway, bash + shellcheck.

**Spec:** `docs/superpowers/specs/2026-11-07-cka-lab-design.md`

## Global Constraints

- Go module: `cka-lab`; `go 1.26` в `go.mod`. Зависимости только через `flake.nix` `devShell`; `/etc/nixos` не трогать; без `pip`/`npm -g`.
- Kubernetes **v1.37** — одна переменная `K8S_VERSION="1.37"` в `scripts/common.sh` (пакеты из `pkgs.k8s.io/core:/stable:/v1.37/deb/`).
- Ноды: `controlplane` 192.168.56.10 (2 CPU, 4096 MB), `node01` 192.168.56.11, `node02` 192.168.56.12 (2 CPU, 2048 MB). Box `bento/ubuntu-24.04` (fallback `generic/ubuntu2204`). Synced folder `type: "rsync"`, исключить `.git/`, `.lab/`.
- Весь UI, вопросы, задания, сообщения API — на английском.
- `.lab/` в `.gitignore`: `kubeconfig` (`chmod 600`), `ssh_config`, `token`, `progress.json`, `cka-lab` (бинарник), `server.pid`, `server.log`. kubeconfig никогда не печатать в stdout/логи.
- Claude не запускает `vagrant up/halt/destroy/snapshot`, `./lab up/reset/selftest`, `kubectl apply/delete` и `ssh` на ноды: в шагах с пометкой **[USER]** Claude даёт команду и ждёт результат от пользователя.
- Bash: `set -euo pipefail`, комментарий «зачем», `shellcheck` чистый.
- Уровень: ровно 10 вопросов, ровно 7 заданий. Теория сдана при ≤1 ошибке; на 2-й ошибке блок завершается fail, retry перемешивает порядок вопросов и вариантов.
- Койны (`config.yaml`): `easy: 10`, `medium: 20`, `hard: 30`, `levelBonus: 50`, `repeatPercent: 30` (floor). Теория 0. Магазин: `break-5` 5 мин 30, `break-15` 15 мин 80, `break-30` 30 мин 150.
- «Первое решение» считается по всем режимам (`SolvedCount[taskID] == 0`). Прохождение уровня — только решения в режиме `levels`. Бонус уровня — один раз. Reveal до решения → задание всё равно надо решить, награда 0.
- `docs` и `solution` задания отдаются в API только если задание решено в любом режиме или раскрыто.
- Snapshot: одно имя `clean`, всегда на все 3 ноды (`vagrant snapshot save|restore clean` без vm-name), restore с `--no-provision`.
- Лицензии: из `theplatformlab/CKA-Certified-Kubernetes-Administrator` (MIT) можно адаптировать с атрибуцией в `NOTICE` и полем `source:` в задании; из `chadmcrowell/CKA-Exercises` (без лицензии) — только идеи, без текста.

## Review Focus

1. **Повторный Check / двойной клик после pass** — койны начисляются один раз за попытку (Start → pass). Тест в Task 9: `TestCheckTask_SecondCheckAfterPassAwardsNothing`.
2. **Кластер недоступен (VM остановлены)** — Check возвращает `ErrClusterUnavailable` (HTTP 503, понятное сообщение), задание не засчитано, койны не начислены. Тест в Task 9 и Task 10.
3. **Идёт откат snapshot, пользователь стартует/проверяет другое задание** — `ErrClusterBusy` (HTTP 409). Тест в Task 9.
4. **Namespace задания остался от прошлой попытки с мусором пользователя** — Start удаляет namespace и ждёт его исчезновения, потом создаёт заново. Тест в Task 6: `TestPrepareTask_RecreatesExistingNamespace`.
5. **`progress.json` повреждён** — сервер не стартует с ошибкой, файл не перезаписывается; отсутствующий файл = пустое состояние. Тест в Task 7.

    Type        string       `json:"type"`        // resource | podsReady | canI | command
    Description string       `json:"description"`

    Assert      []Assertion  `json:"assert,omitempty"`     // resource
